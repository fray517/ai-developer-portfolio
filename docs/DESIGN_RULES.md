## 1. Назначение
Точные обязательные правила визуальной реализации всех секций. При конфликте оформления и содержания приоритет — достоверность, читаемость, функциональность. Изменения согласованных параметров должны отражаться в документе.

Основной фон `--bg-primary`, секции могут чередоваться с `--bg-secondary`, карточки — `--surface`. Основной текст — `--text-primary`, вторичный — `--text-secondary`. `--accent` — для ссылок/акцентов только при достаточном контрасте; главная кнопка — `--button-primary` с белым текстом. Не передавать смысл только цветом. Контраст WCAG AA: обычный текст не менее 4.5:1, крупный — не менее 3:1. Если сочетание не соответствует норме — корректировать применение. Не использовать много конкурирующих или неоновых акцентов.

**Основной шрифт:** Manrope, резервный Arial, sans-serif; начертания 400/500/600/700/800 при необходимости; кириллица обязательна, без зависимости от внешнего шрифта для корректного отображения.

| Вторичный текст | 16 px | 15 px |

Высота строки: H1 1.1; H2 1.15; H3 1.25; основной текст 1.6; кнопки 1.3. Не более двух семейств; строка около 65–75 символов; избегать длинных заголовков, наложений при переносах, слишком мелкого текста. Допускается `clamp()` между указанными граничными размерами.

## 4. Сетка и контейнеры
Максимальная ширина контейнера **1200 px**, центрирование. Боковые отступы: десктоп 32 px, планшет 24 px, смартфон 20 px. Базовая сетка десктопа 12 колонок с интервалом 24 px. Отступы секций сверху и снизу: десктоп 112 px, планшет 80 px, смартфон 64 px. Шкала отступов: `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 112 px`. Выравнивание по сетке, смысловое разделение воздухом, без случайных отрицательных смещений и переполнения.

## 5. Hero
Десктоп: две колонки, текст примерно **55%**, визуал интерфейсов примерно **45%**. Текст слева; основная кнопка рядом со «Смотреть проекты». Визуал трёх проектов: репетитор, «Читалка», Auto-RAG; один акцентный, другие дополняют. Без вымышленных скриншотов; при отсутствии реальных — явно обозначенные концептуальные схемы.

На смартфоне до 767 px одна колонка: заголовок → описание → главная кнопка → вторичное действие → визуал. Без горизонтального переполнения.

## 6. Карточки проектов
Три большие горизонтальные карточки, подряд. Десктоп: ~50% текст и ~50% изображение; соседние могут зеркалиться. Параметры: фон `--surface`, радиус **20 px**, внутренние отступы **40 px**, промежуток **32 px**, граница **1 px `--border`**, тень слабая или отсутствует.

Внутри: номер, название, задача, функции, подтверждённые технологии при наличии, статус **«В разработке»**, скриншот или концептуальная схема, проверенная ссылка при наличии. При наведении — небольшое изменение фона/границы, подъём не более **3 px**, длительность **180–220 ms**. Клавиатурный фокус на интерактивных элементах; некликабельная карточка не должна выглядеть кликабельной. Мобильный вариант вертикальный, отступы **24 px**, изображения без потери важного содержания.

**Для учебного лендинга:** все три карточки статические заглушки. Не создавать кнопки демо, не требовать рабочие AI-приложения.

## 7. Кнопки и ссылки
**Основная кнопка:** фон `--button-primary` **#246FC3**, текст **#FFFFFF**, высота не менее **48 px**, горизонтальные отступы **24 px**, радиус **12 px**, вес **600**, переход `background-color 180ms ease`. Адрес `https://t.me/Denis_Fedc`.

**Вторичная:** фон прозрачный, текст `--text-primary`, граница `--border`, высота **48 px**, радиус **12 px**; ведёт к портфолио.

Состояния: default — обычное; hover — умеренный сдвиг цвета; `focus-visible` — контрастная рамка **3 px**; active — лёгкое затемнение; disabled — только для реально недоступных действий. Нет неработающих демо-кнопок; внешние адреса корректны.

## 8. Технологии
Компактная сетка тематических групп: радиус панелей **16 px**, внутренний отступ **24 px**, промежуток **16 px**, без избытка логотипов. Публиковать конкретные технологии только после подтверждения применения/владения. На телефоне одна или две колонки по доступной ширине.

## 9. Процесс работы
Пять этапов: обсуждение задачи → прототип → разработка → тестирование → подготовка к внедрению. На десктопе горизонтальная композиция либо сетка, на телефоне вертикальная последовательность. Сохранять порядок. Это предлагаемый процесс, не доказательство реализованных коммерческих проектов.

## 10. Анимации
Минимальное функциональное движение. Появление элементов **250–400 ms**, наведение **180–220 ms**, `ease-out`, сдвиг не более **12 px**. Без бесконечных эффектов, резких увеличений, постоянного движения больших текстов, блокировки взаимодействия. При `prefers-reduced-motion: reduce` отключать ненужные анимации и плавную прокрутку.

## 11. Адаптивные правила
Диапазоны: мобильный **до 767 px**, планшет **768–1023 px**, десктоп **от 1024 px**. Тестовые ширины: **375, 390, 768, 1024, 1440 px**, плюс промежуточные при необходимости. Нет горизонтального скролла из-за вёрстки, обрезанного текста и вышедших за контейнер изображений. Кнопки удобно нажимать, карточки логичны, клавиатурная навигация доступна; масштаб браузера не разрушает основные сценарии.

## 12. Изображения
Приоритет: (1) настоящие скриншоты, (2) содержательные схемы, (3) концептуальные иллюстрации с явным обозначением статуса. Форматы WebP, PNG, SVG по назначению. Для интерфейсов `object-fit: contain` при необходимости полного показа. Содержательные изображения — с `alt`, декоративные не дублируются для вспомогательных технологий. Не создавать ложного впечатления готовности AI-приложений.

## 13. Доступность
Клавиатурная доступность интерактивных элементов; видимый фокус; семантические заголовки и ссылки; понятные подписи; контраст по WCAG AA; работа без анимации; отсутствие функций, доступных только при hover.

## 14. Технические ограничения
Один автономный **`index.html`** со встроенными HTML/CSS/JavaScript, локальное открытие. Без обязательного backend, форм заявок, базы данных и сервера. Допустимы встроенные изображения; внешние шрифты необязательны для корректного отображения. Реальные AI-приложения в рамках данного ДЗ не разрабатываются и не запускаются.

## 15. Запреты
Нельзя выдавать проекты за завершённые, выдумывать отзывы, клиентов, результаты или ссылки; делать фиктивную интерактивность, перегружать страницу анимациями и декором, менять утверждённую структуру и параметры произвольно.
